02 / Current systems

What the source already contains.

Existing implementation is a starting point for review, rather than a final design commitment.

MovementSource present

Move, jump, dash

Camera-relative movement with ground and air acceleration, friction, gravity, capsule-cast collision sliding, and step handling. The model faces camera-forward.

Assets/Scripts/PlayerController.cs
Camera & targetingSource present

Automatic aim selection

Cinemachine third-person following and a crosshair-based target search with a visibility raycast. The configured targeting range is 20 units, with a radius of 6.5% of screen height. The crosshair changes color when a target is selected.

Assets/Scripts/LockOnAim.cs
WeaponsSource present

Held fire & pooled bullets

Attack fires while held, using a 0.25-second cooldown and either a selected target or the camera crosshair ray. Bullet pools start at 30 per type and expand as needed.

ShootingController.cs · BulletManager.cs
Projectile dataConfigured

One default bullet type

The default asset sets damage to 10, speed to 20 units/second, and lifetime to 30 seconds. Gravity and piercing are disabled; impact effects and audio are unassigned.

Assets/Scriptable Objects/DefaultBulletType.asset
Scene connections

The scene instantiates Player, ThirdPerson Camera, and PrototypeMap prefabs, with a HUD crosshair and a Target object. It supplies both camera/crosshair pairs, the movement controller's aim reference, the shooting controller's bullet manager, and the camera tracking target. These seven references resolve in the scene file; their behavior still needs a runtime check.

Still missing from authored code

The six scripts in Assets/Scripts/ do not implement enemy AI, a health/death receiver, mech assembly, or a run/progression loop. IDamageable defines a damage interface, but no implementation was found there. The player prefab has no Animator or skinned-mesh component.

Source observations and existing TODOs
  • Shooting audio: the shootSound branch in ShootingController.cs calls muzzleFlash.Play(). Both references are currently unassigned in the player prefab.
  • Piercing state: HandleBulletImpact receives a BulletData struct by value, so its penetration decrement is not written back to the active bullet. Piercing is disabled in the default type.
  • Existing project TODOs: investigate slope/step behavior across frame rates, improve lock-on and camera references, review movement mathematics, clean up code, and compare ground-check/skin-width approaches.

These are file-level observations, not reproduced runtime defects. No fixes were applied. Existing TODOs were translated from Assets/AAA/TODO.txt.
